A gramática formal
e o autômato

Um compilador não adivinha. Ele recebe texto e o processa através de uma Gramática Livre de Contexto G = (V, Σ, R, S).

O analisador léxico converte caracteres em tokens usando um Autômato Finito Determinístico (DFA). Cada caractere é consumido exatamente uma vez em tempo estritamente linear.

As partículas se ordenam nos anéis de estados determinísticos: a desordem vira um pipeline sem retrocesso.

Como o processador
toma decisões

Por que encadear dez if-else é um crime contra a latência? Cada teste exige uma instrução de comparação e salto condicional: O(n) no pior caso.

Um switch denso compila na JVM diretamente para tableswitch: o processador calcula o endereço de destino em um único ciclo O(1), indexando a tabela de offsets.

Veja as partículas organizadas em colunas de saltos diretos: zero busca sequencial, tempo imediato.

FASE 05 · O ENIGMA ONTOLÓGICO

Quem compila
o primeiro compilador?

Se o compilador de C é escrito em C, e o compilador de Java é escrito em Java, onde começou a primeira cadeia de montagem?

Para compilar um programa na linguagem L, você precisa de um compilador executável. Mas para criar esse compilador, você precisa escrevê-lo na linguagem L. É o paradoxo do ovo e da galinha no silício.

As partículas dobram-se num anel de Möbius tridimensional: uma auto-referência infinita que exige uma saída física de engenharia.

FASE 06 · A SOLUÇÃO
v0 → v1 → v2
OS TRÊS TOMBSTONES

O milagre do
Bootstrapping

A resposta da ciência da computação chama-se Self-Hosting Bootstrapping:

1. v0Escrito em Assembly/C existente
2. v1Escrito na linguagem nova, compilado por v0
3. v2O código v1 compila a si mesmo

Quando v1 compila v1 e produz exatamente v2, o cordão umbilical é cortado. A linguagem atinge auto-suficiência ontológica.

FASE 07 · O FANTASMA NO BINÁRIO
1984
KEN THOMPSON TURING AWARD

O cavalo de Troia
auto-replicante

Em 1984, Ken Thompson provou a vulnerabilidade mais profunda da história: Reflections on Trusting Trust.

Ele modificou o compilador C para injetar um backdoor no comando login, E TAMBÉM para injetar a própria rotina de infecção toda vez que recompilasse o código do compilador.

O código-fonte estava 100% limpo. O binário estava infectado. É a prova do Teorema da Recursão de Kleene: a confiança no software nunca é transitiva.

Por que o caixa de loja
não pode usar nuvem

A aula encerrou com uma prova no varejo. A Fórmula de Kingman para filas G/G/1 governa o tempo de espera:

Se a latência do serviço salta de 50 ms (local) para 3.000 ms (nuvem com oscilação), a intensidade de tráfego ρ → 1 e o tempo de fila Wq explode para o infinito.

O caixa trava. A fila física do supermercado vira motim. A única resposta é a Doutrina Soberana: daemons locais em Java/Linux que funcionam offline com compilação determinística.
